THE PROBLEM

Linters check if the code is correct.
Nobody checks if the claims are true.

These are the failures a normal review and your CI never catch — the gap an AI (or a rushed dev) leaves behind:

✗"Added tests for X" — but the diff adds none, or weakens existing assertions.
✗The implementation quietly drifted away from the spec it was supposed to follow.
✗A commit/PR/README claims a dependency or change that the manifest/diff doesn't support.
✗A design that was supposed to be discarded got silently resurrected.
